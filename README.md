# shared

Cross-module content for the SomaSafe monorepo: things more than one of
`application/`, `backend/` and `firmware/` needs, so they can't live inside just one of
them.

- **`docs/`** — topic docs for things that would otherwise be duplicated across the
  per-module READMEs (architecture, security, protocols, versioning semantics, ...). Each
  module's README covers what's specific to it and links here for shared background.
- **`dataset.proto`** — the capture-import protobuf. `make setup` compiles the Python
  bindings once into `gen/code/`, where both the backend (which writes the exports) and
  the firmware harness (which replays them) import them as `shared.gen.code.dataset_pb2`;
  the Android app generates its own with the protobuf Gradle plugin.
- **`Makefile`** — `make setup`: generates the server's ECDSA P-256 signing keypair into
  `gen/` (see [docs/model-signing.md](docs/model-signing.md)) and the protobuf bindings
  above. Idempotent, and run by every module's `make shared`.
- **`gen/`** — build output from one project consumed by another: the dataset, the
  exported models and the subject exports (`gen/exports/`) from the backend, the factory
  NVS image (incl. keys) and the published firmware image from the firmware, plus
  `gen/code/` for the protobuf bindings `make setup` generates. Gitignored; regenerated by
  each project's own scripts.

## How it's linked

Every module has a convenience `make shared` target: it links `../shared` when run from
inside this monorepo layout, or, when that path doesn't exist, clones
[`memoria-somasafe-shared`](https://github.com/papyroplastics/memoria-somasafe-shared.git)
into `shared/` (gitignored) so the module builds standalone outside the monorepo too. It
then runs `make -C shared setup`, which generates the signing keypair and the protobuf
bindings, so both sides get the same generated code from one place. `protoc` must be on
the PATH.
